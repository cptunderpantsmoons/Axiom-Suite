1. What Helm Is

Helm is a single control plane between a company's AI tools (Claude Desktop/Code, Cursor, Cline, custom agents) and upstream LLMs (OpenAI, Anthropic, NVIDIA NIM, Nous, and free-tier suppliers). It governs every model call: who may call (hashed hk_ keys + roles), what it costs (soft/hard budgets + cost-aware routing, GPU-hour for self-hosted), what it may say (a security Guardian, policy engine, PII redaction), and records it all (an immutable hash-chained audit log + cryptographically-signed provenance).

2. Quick Start

go build ./...                    # or: make build
# two services (share Redis for cross-process state):
MH_REDIS_ENABLED=true ./bin/management-harness-proxy &
MH_MANAGER_ADMIN_TOKEN=... MH_MANAGER_JWT_SECRET=... ./bin/management-harness-manager &
  • Proxy :8080 — OpenAI-compatible /v1/chat/completions, /stream, /v1/messages
  • Manager :8090 — /api/v1/... + embedded dashboard at /
  • Readiness: /healthz, /readyz, /livez, /metrics

Open http://localhost:8090/, sign in with the manager admin token, create an operator + mint an hk_ key, and call the proxy with Authorization: Bearer hk_....

3. Architecture

AI Tool ──► PROXY ─ auth ─ guardian(ORIGINAL) ─ [skill expand] ─ guardian(re-scan)
                ─ optimize ─ budget(EstimateCost) ─ router/selectProvider ─► LLM
                  ├─ Metrics (Prometheus /metrics)
                  ├─ Audit (hash-chained, immutable)
                  └─ Manager API + Dashboard (:8090)

Guardian always scans the original prompt; a used skill is re-scanned; optimization runs after the guardian and before budget/routing so the charge matches the tokens actually sent.

7. Local inference (self-hosted) & GPU-hour accounting

providers:
  local:
    type: local
    base_url: "http://vllm:8000/v1"
    enabled: true
    local:
      gpu_hour_cost: 2.5
      gpu_count: 1
      declared_throughput_tps: 90
      safety_factor: 1.25
      min_gpu_seconds_per_request: 3

A shared H100-70B lands ~$1–3/1M tokens (vs ~$1k+ hosted); the per-request GPU-second floor prevents tiny requests from evading the budget. Budget pre-check and post-usage both use this model, so the Cost page shows real GPU cost.

8. Skills

A Skill = system_prompt + template (with {{slot}}) + parameters + permissions. Create via the dashboard or Draft with AI (the configured LLM generates a full skill from a description). Invoke by adding fields to the request:

{ "model":"gpt-4o", "skill":"support-reply",
  "skill_params": { "message":"My order hasn't arrived", "tone":"professional" } }

Unknown skill → 404; unauthorized → 403; invalid params → 400. Optimization opt-in per skill via optimize:true.

9. Prompt optimization & cost

Lossless (default): collapses redundant whitespace. LLM-based (via optimizer): a provider model compresses the prompt behind a semantic-preservation gate. Savings appear on the Cost page and as harness_optimizer_* metrics. The Cost page aggregates per-operator budgets, total spend, and optimizer tokens saved.

10. Provenance — Proof of Source / Proof of Human

Sign data entering critical pipelines with an attested source (human/model/unknown) and verify it wasn't synthetically altered or model-poisoned. Ed25519-signed attestations bind the payload's SHA-256 hash to a signer + source + timestamp.

  • Sign: POST /api/v1/provenance/sign {source, payload_base64} → a signed record (admin).
  • Verify: POST /api/v1/provenance/verify {record, payload_base64} → {"verdict":{...},"proof_of_human":true|false}. Payload change or source re-attribution fails.
  • Middleware: provenance.Middleware(pub, requireValid) on ingestion routes verifies an X-Helm-Provenance header and fail-closes (403) on tampered data, or exposes Verdict.HumanProof().
  • Key: GET /api/v1/provenance returns the verifier public key; set MH_PROVENANCE_PRIVATE_KEY (base64) for persistence across restarts/air-gap.

Use case: gate RAG/enterprise ingestion on proof_of_human, or quarantine anything signed model (synthetic).

11. Security & compliance

  • Keys hashed at rest; secrets never leave as plaintext (masked in dashboard).
  • Guardian blocks prompt injection, jailbreaks, tool escalation; redacts PII.
  • Immutable audit chain: GET /api/v1/audit/verify proves integrity; /audit/export for SIEM.
  • Provable provenance (above) for data-integrity and anti-poisoning.

14. Troubleshooting

SymptomFix
503 “no provider available”Enable a provider in Configuration → Providers.
401 “invalid API key”Enable MH_REDIS_ENABLED=true so manager-minted keys are shared with the proxy.
“insecure default” panicSet real MH_MANAGER_ADMIN_TOKEN/MH_MANAGER_JWT_SECRET.
Settings saved but proxy unchangedProviders/keys reload live; other settings apply on restart.
Provenance fails after restartSet a persistent MH_PROVENANCE_PRIVATE_KEY (else key is ephemeral).
